# AI-use provenance record

Machine-readable, per-release record of which files in this repository were created or
materially refactored with the assistance of a generative-AI tool, which tool and version was
used, what the assistance covered, and who reviewed the result.

This file exists because the venue's policy requires two things a plain prose statement cannot
satisfy: **the application name and version must be reported**, and **code generated by an
AI/LLM must be annotated to that effect**. A per-site annotation of every line was not feasible
after the fact for a 44,005-line TypeScript plus Rust tree that arrived in a single initial
commit, so the annotation is carried at module level: every file listed in the table below
declares its AI-assisted status in a one-line marker in its module header, and this file is what
those markers resolve to. All AI-assisted output was reviewed, is covered by `npm test` and
`npm run typecheck`, and remains under the corresponding author's responsibility.

## Marker convention

The marker is one line, in the comment syntax of the host file, and it makes no claim about
what the code does:

| Syntax | Meaning |
|--------|---------|
| `// AI-PROVENANCE: AI-assisted changes to this file are itemised in docs/AI_PROVENANCE.md.` | TypeScript / Rust source and test file |
| `<!-- AI-PROVENANCE: AI-assisted changes to this file are itemised in docs/AI_PROVENANCE.md -->` | Markdown document |

A marker states that the file carries **recorded AI-assisted changes** in at least one release
row below. It does **not** state that the module as a whole was written by a model, and it is
not a substitute for the table: the scope of assistance is recorded per release, per file.
`src-tauri/tauri.conf.json` deliberately carries **no** marker — strict JSON has no comment
syntax and the file is parsed by `serde_json`, so a comment would break the build; its entry in
the table below is the record.

Markers present in the working tree (2026-10-08):

## Attribution limits

1. `git log` has seven commits, and `6c4d313` ("Initial release of CladeForge 0.1.0") adds the
   entire ~44k-line TypeScript tree and the Rust shell in one step. Nothing in the repository
   distinguishes AI-authored files from hand-authored ones at that commit, so the honest value
   for `v0.1.0` is **not attributed**, not a guessed list.
2. No file was renamed or split by an AI-assisted commit that history can prove, so this record
   cannot list "materially refactored" files for `v0.1.0` either.
3. Rows marked **not attributed** must not be upgraded to a file list by inference from comment
   style, commit-message style, or line counts. Only the author, who knows what was typed and
   what was accepted from a model, can fill them in.

## Anonymisation note

This record names people, tools and machine-local installation paths. It is **not** part of the
`v0.1.0` tree and therefore not part of an archive generated from that tag. If a future
anonymised reviewer artifact ever includes `docs/AI_PROVENANCE.md`, the reviewer name, the
author's home-directory paths and the `/Applications/...` entries must be stripped first, and the
marker lines in the module headers must be checked for the same leak.
